# 0023. 変異テストは依存・設定が変わっても最も新しい結果を引き継ぎ、手元で結果が無ければほかの作業ツリーの結果を写す

## Status

Accepted(2026-10-18、利用者の決定)。[0013](0013-incremental-mutation-on-push.md) の次の部分を置き換える。

- Decision の2のうち、CI のキャッシュの鍵に `package-lock.json`・`stryker.config.mjs`・`vitest.config.ts` の指紋を入れ、指紋が変わる(依存・設定が変わる)と復元せずに全部を走らせる部分。
  鍵はコミットのハッシュだけになり、いつも最も新しく保存された結果を復元する
- Consequences のうち、依存パッケージと Stryker・Vitest の設定の変更を、キャッシュの鍵の指紋で埋める部分
- Consequences の、手元の実行が同じ結果ファイルを引き継ぐ部分に、結果ファイルが無いときはほかの作業ツリーの結果を写して始めることを足す

0013 の走らせ方の3段(commit の前には走らせない・push では変わった変異体だけ・全体は週1回手で `--force`)、対象(`stryker.config.mjs` の `mutate`)、
しきい値、[0021](0021-fail-on-mutation-timeout.md) の判定(時間切れを落とす・落とせなかった変異体と時間切れを引き継がない)は変えない。
依存・設定の変更で全部を測り直さなくなり、変異テストが見る範囲が狭まるので、[0011](0011-extreme-constraints.md) に従ってこの ADR で決める

一部を [0025](0025-remeasure-kills-on-test-deps.md) が補った(2026-10-19。Consequences の、週1回の `--force` に頼る所のうち 0013 の穴と、写す元と import する別のファイルが違っても比べない部分のうち、テストから import をたどって届く src・content のファイルは比べ、変わればそのテストが前回落とした変異体を測り直すようになった。写すときは写す元の隣の指紋も使う。依存・設定の変更を週1回の `--force` に任せる部分は変えない)

## Context

決める前(`50e3e70`)のこのリポジトリは次の状態だった。

- **CI のキャッシュの鍵は、3つのファイルの指紋とコミットのハッシュだった。** `.github/workflows/deploy.yml` の鍵は
  `stryker-incremental-${{ hashFiles('package-lock.json', 'stryker.config.mjs', 'vitest.config.ts') }}-${{ github.sha }}` で、`restore-keys` も同じ指紋で始まっていた(0013 の Decision の2)
- **CI はほとんど前回の結果を引き継げていなかった。** 2026-10-18 の時点の直近の deploy 13回のうち、前回の結果を引き継いだのは2回(4141体を使い回し、38秒)だけで、
  残りは `Cache not found` の後に Stryker が `No incremental result file found ... a full mutation testing run will be performed` を出し、全部を走らせていた(約15分)。原因は次の2つ
  - 3つのファイルのどれかが変わると指紋が変わる。注釈だけを変えた commit でも変わる
  - PR の方式だった頃、PR の側で保存したキャッシュが `main` からは見えなかった(PR の方式は [0020](0020-direct-push-to-main.md) でやめた)
- **手元は、結果ファイルがある作業ツリーでだけ引き継げていた。** 結果ファイル(`stryker.config.mjs` の `incrementalFile`。git は追跡しない)がある作業ツリーでは変わった変異体だけが走り、
  4070体のうち4059体を使い回して36秒だった。新しく作った作業ツリーには結果ファイルが無く、最初の1回は全部が走っていた

2026-10-18、利用者が AskUserQuestion で「変異テストはローカルでも CI でも差分だけを回したい。1週間に1回全体を定期的に回すのは後の課題」と答え、
入れる先として「CI・ローカル両方」を選んだ。

## Decision

1. **CI のキャッシュの鍵から指紋を外す。** 鍵は `stryker-incremental-${{ github.sha }}`、`restore-keys` は `stryker-incremental-` にし、いつも最も新しく保存された結果を復元する。
   指紋を入れていた頃の名前(`stryker-incremental-<指紋>-<コミットのハッシュ>`)の結果も同じ接頭辞なので、`restore-keys` で復元される。
   保存の条件(変異テストが落ちても保存し、取り消された実行は保存しない)は変えない
2. **手元で結果ファイルが無ければ、ほかの作業ツリーの結果を写して始める。** `npm run test:mutation` の入口 `scripts/run-mutation.mjs` が、Stryker を呼ぶ前に、
   同じリポジトリの作業ツリー(`git worktree list --porcelain`)の結果ファイルのうち、更新時刻が最も新しいものを写す。写した元を1行出す。
   どこにも無ければその旨を1行出し、Stryker が全部を走らせる
   - `--force` のとき(全部を測り直す)と、`--incrementalFile` で結果ファイルを名指ししたときは写さない
   - この作業ツリー自身の結果ファイルは候補から外す。JSON として読めない候補(ほかの作業ツリーの Stryker が書いている途中のもの・書き込みが中断されたもの)は1行出して飛ばし、
     読めたものの中で最も新しいものを写す。読めない写しはこの作業ツリーに残さない
   - `git worktree list` が失敗したとき(git が無い・リポジトリの中でない)も1行出し、写す元が無いときと同じく Stryker が全部を走らせる
   - 結果ファイルの `files`・`testFiles` の名前はリポジトリ直下からの相対なので、別の作業ツリーの結果もそのまま比べられる
   - CI の checkout にはほかの作業ツリーが無いので、CI の振る舞いは1だけで決まる
3. **全部を測り直すのは、0013 のとおり週1回、手で `npm run test:mutation -- --force`。** 週1回の実行を定期的に走らせる形(CI の `schedule` など)は、利用者が後の課題にした

## Consequences

- **失うもの: 依存パッケージ・Stryker の設定・Vitest の設定が変わっても、全部を測り直さない。** その変化で結果が変わった変異体は、次の全体の実行(週1回。今は手で、定期的に走らせるのは後の課題)まで前回の結果が使われる。
  たとえば依存の版上げでテストの振る舞いが変わり、前回落とした(Killed)変異体が今は生き残るとしても、落としたままと数える。
  逆向き(前回の生き残り・どのテストも通らない・時間切れを使い回す)は、0021 までのとおり `scripts/run-mutation.mjs` が毎回測り直すので起きない
- **週1回の `--force` に頼る所が増える。** 0013 の穴(`mutate` のファイルやテストが import する別のファイルの変更)に、依存・設定の変更が加わる。週1回を忘れると、どちらの見落としも残ったままになる
- **作業者に、依存・設定を変えたときの `--force` を求めていた [../agents/verification.md](../agents/verification.md) の決まりもやめる。** 依存・設定を変えたときも既定の実行(変わった変異体だけ)で済ませ、全部を測り直すのは週1回に任せる
- **CI は、依存・設定が変わった push でも前回の結果を引き継ぐ。** 引き継げた回は、上の実測で38秒だった(全部を走らせると約15分)。この形での push ごとの時間は、この記録の時点では CI で測っていない
- **手元の新しい作業ツリーの最初の1回も、ほかの作業ツリーの結果を引き継ぐ。** 2026-10-18 に、結果ファイルの無い新しい作業ツリー(`50e3e70`)で `npm run test:mutation` を走らせると、
  同じ commit の別の作業ツリーの結果を写し、4070体すべてを使い回して1分20秒で通った(同じ時間に、ほかの作業ツリーで統合テストが走っていた)
- 写す元の作業ツリーが別の commit や手元の変更の途中でも、Stryker は `mutate` のファイルとテストファイルの中身を比べ、変わった所の変異体を走らせ直す。
  写す元と依存・設定・import する別のファイルが違っても比べない(1つ目の項目と同じ穴)
- 最も新しく保存された結果が、すぐ前の commit のものとは限らない(`concurrency` の `cancel-in-progress` で取り消された実行は保存しない)。そのときは上と同じく、変わった所の変異体が走る
- `npx stryker run` を直接叩くと、ほかの作業ツリーの結果を写さない(`scripts/run-mutation.mjs` の外)

## Alternatives Considered

- **0013 のまま、鍵に指紋を入れ続ける** — 直近の deploy 13回のうち2回しか引き継げていなかったことから、利用者が退けた
- **CI と手元のどちらか片方だけに入れる** — 利用者が「CI・ローカル両方」を選んだ
- **週1回の全体の実行を CI の `schedule` のワークフローで走らせる** — 利用者が後の課題にした。この ADR では作らない
- ほかに比べた案の記録は無い
