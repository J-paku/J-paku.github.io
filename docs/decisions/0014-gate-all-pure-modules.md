# 0014. 変異テストとファイル別カバレッジ100%の対象を、手で並べた7ファイルから純粋モジュールの全部へ広げ、新しいファイルを自動で入れる

## Status

Accepted(2026-10-11、利用者の方針)。[0011](0011-extreme-constraints.md)の「ファイル別100%とミューテーションの対象」のうち、
対象を新しく作ったファイルに限り(「既にあるファイルを遡って全部を対象にはしない」)、作るたびに設定の一覧へ手で足す部分を置き換える。
しきい値(変異テストの`break` 100・ファイル別の`FULL_COVERAGE`)と、走らせ方([0013](0013-incremental-mutation-on-push.md))は変えない

## Context

- 0011の時点の対象は手で並べた一覧だった。変異テストは`stryker.config.mjs`の`MUTATE`に7ファイル、ファイル別100%は`vitest.config.ts`の`FULL_COVERAGE_FILES`に同じ7ファイルと`src/lib/pixel/flight-art.ts`。
  新しい純粋モジュールを作った人が両方へ足す約束で、足し忘れると黙って門の外に残る
- 一覧の外の既存の純粋モジュールは、どちらの門にも入っていなかった
- 2026-10-11の調査で、純粋モジュールの置き場の規則(下の[Decision](#decision))に当たるファイル72個の変異スコアを、静的な変異体(モジュールを読む時に1回だけ評価される式の変異体)を含めて測り、91.1%だった
- 同じ日に、生き残った変異体をテストを足して落とし、テストでは見分けられない変異体(等価な変異体)はソースを同じ振る舞いの別の書き方に直して消し、データのファイルを除く全部を100%にした
- 利用者の方針: 新しい純粋モジュールは自動で門に入る形にする(一覧へ手で足すのを忘れる穴を無くす)

## Decision

1. **対象は純粋モジュールの置き場にある`.ts`の全部。** 一覧を手で並べず、`scripts/gate-targets.mjs`が設定を読むたびに`src`をたどって規則で選ぶ。
   `stryker.config.mjs`の`mutate`は`MUTATION_TARGETS`、`vitest.config.ts`のファイル別100%は`COVERAGE_TARGETS`を使う。新しいファイルは置いた時点で両方の対象になる
   - 含める: `src/lib/**/*.ts`・`src/utils/**/*.ts`・`src/components/**/utils/**/*.ts`
   - 外す: テスト・`*.d.ts`・`*.fixture.ts`・`*.test-helper.ts`・`types.ts`・`hooks`フォルダの下
2. **データのファイルは名指しで扱いを分ける。** 外す理由の正本は`scripts/gate-targets.mjs`の注釈
   - どちらの門にも入れない: ドット絵の行列(`actors.ts`・`fishing-art.ts`・`structures.ts`・`terrain.ts`・`umbrella-original.ts`・`weather-art.ts`)と、
     `linkedom`の差し替え(`src/utils/linkedom-browser-stub.ts`。`window`の`DOMParser`を渡す1行だけ)。絵のデータは0011の時点でも対象外で、ファイル別100%で固めるかは決めていない
   - 変異テストから外し、ファイル別100%だけで固める: `src/lib/pixel/flight-art.ts`(0011の時点と同じ)と`src/lib/pixel/palette.ts`(色の表)。
     色の表の変異体は82体がすべて静的な変異体で、2026-10-11の実測では6体が生き残った。夜だけ出る絵にしか使わないキーの昼の値と、どこからも読まれていない`roofColors`を変えるもので、絵にも振る舞いにも表れず、表を丸ごと写したテストでしか落とせない
3. **名指ししたパスが1つでも実在しないと、`scripts/gate-targets.mjs`を読み込む時点で落とす。** 0011で一覧に置いた存在の検査と同じ意味で、名指しが空振りしたまま黙って通らないようにする。
   拾った対象が0件のときも落とす
4. **モジュールを読む時に投げうる変異体があるファイルは、テストの中で`vi.resetModules()`してから動的に`import`する。**
   トップレベルの検査や定数の組み立てを壊した変異体は、テストファイルの`import`で投げてVitestの収集エラーになり、Strykerはそれを生き残り(Survived)と数えるため。
   2026-10-11に、読み込む時に投げる表を持つ使い捨てのモジュールを静的な`import`のテストで測り、読み込みで投げる変異体3体がどれもSurvivedと数えられるのを確かめた

## Consequences

- 2026-10-11の手元の実測(このADRと同じ変更の作業ツリー):
  - 変異テストの全体(`npm run test:mutation -- --force`): 73ファイル・3639体(うち静的な変異体1253体)。落とした3616体・時間切れ23体・生き残り0・どのテストも通らない0で、100.00%。
    かかった時間は12分12秒(最初のテスト実行が59秒)。0011の7ファイルの全体は6分7秒だった([0013](0013-incremental-mutation-on-push.md))
  - 続けて既定の実行(`incremental`): 3639体すべての結果を引き継ぎ、100.00%。1分11秒(最初のテスト実行が57秒)
  - ファイル別100%は75ファイル(変異テストの73と、`flight-art.ts`・`palette.ts`)ですべて通る。全体の床は実測(statements 85.28%・branches 85.62%・functions 79.24%・lines 84.49%)から決め方どおり上げた(正本は`vitest.config.ts`)
  - テストを持たない純粋関数のファイルを`src/utils/`に1つ置くと、`npm run test:coverage`がそのファイルのstatements・branches・functions・linesの4つで落ちた(確かめた後に消した)。新しいファイルが自動で門に入ることの確認
- **CIの最初の実行は全体が走る。** この変更は`stryker.config.mjs`と`vitest.config.ts`を変えるので、CIのキャッシュの鍵の指紋が変わり、前回の結果を引き継がない([0013](0013-incremental-mutation-on-push.md))。
  手元の全体は約12分だった。CIの実行機での時間は測っていない
- 純粋モジュールを変えたcommitは、どれも`npm run test:coverage`と`npm run test:mutation`の対象になる。0011の時点より、手で走らせる場面が増える
- 0013の`incremental`の穴(対象のファイルがimportする別のファイルだけが変わったときは前回の結果を使い回す)は残る。対象が広がったので、穴に当たる組(変えたファイルを別の純粋モジュールがimportしている)も増える。埋め方は0013と同じく週1回の`--force`
- `scripts/gate-targets.mjs`はCIのキャッシュの鍵に入っていない。規則や名指しを変えて対象が増えたファイルは前回の結果を持たないので、引き継ぎの実行でも全部の変異体が走る
- 色の表は変異テストの外にあるので、表の値の誤りは変異テストでは見つからない。ファイル別100%と、表を使う側(`sprites.ts`)のテストで見る

## Alternatives Considered

- **一覧を手で並べ続け、新しいファイルを作るたびに足す**(0011の形) — 足し忘れると黙って門の外に残るため、利用者の方針で採らない
- **色の表も変異テストに入れる** — 生き残る6体を落とすには表を丸ごと写したテストが要るだけで振る舞いは守れず、それ無しでは`break` 100を満たせないため採らない
- ほかに比べた案の記録は無い
