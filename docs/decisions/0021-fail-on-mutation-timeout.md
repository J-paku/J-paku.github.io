# 0021. 変異テストで、時間切れ(Timeout)の変異体が1体でもあれば落とす

## Status

Accepted(2026-10-18、利用者の決定)。`npm run test:mutation` は、生き残り(Survived)・どのテストも通らない(NoCoverage)変異体に加えて、
時間切れ(Timeout)の変異体が1体でもあれば落ちる。[0011](0011-extreme-constraints.md) が門に置いた変異テストの制約を上げる向きの変更で、
0011 が ADR を求める「下げる」向きには当たらないが、利用者の決定と、失うもの・新しく生まれる負担を残すために書く。

[0013](0013-incremental-mutation-on-push.md) のうち、「走らせた変異体と引き継いだ結果を合わせて`break` 100で判定する」を置き換える。
判定は`break` 100に「時間切れが1体も無い」を足したものになり、時間切れは前回の結果から引き継がない。
0013 の走らせ方の3段(commit の前には走らせない・push では変わった変異体だけ・全体は週1回手で`--force`)、対象(`stryker.config.mjs`の`mutate`)、しきい値は変えない

## Context

決める前(`4707acf`)のこのリポジトリは次の状態だった。

- **Stryker 10.0.0 は時間切れを落とした数に入れて点数を出す。** 点数を出す `mutation-testing-metrics` の `dist/src/calculateMetrics.js` は、落とした数を `timeout + killed` とする。
  そのため時間切れがあっても点数は100のままで、`thresholds.break` 100を通る
- 2026-10-18 に手元で確かめた。数を数えながら回る `for` ループ1つの使い捨てのモジュールを `src/utils/` に置き、`npm run test:mutation -- --mutate <そのファイル>` を走らせると、
  7体のうち `i++` を `i--` にした1体が時間切れ、残る6体が落とした変異体で、点数100.00・終了コード0で通った(確かめた後に消した)
- [0014](0014-gate-all-pure-modules.md) の記録した全体の実行(2026-10-11)では、3639体のうち23体が時間切れで、100.00%と数えて通っていた
- `npm run test:mutation` の入口 `scripts/run-mutation.mjs`(`0910cf4`)は、前回の結果ファイルから生き残り・どのテストも通らない変異体を取り除いて毎回測り直させ、
  時間切れは落とした変異体と同じく引き継いでいた
- 待ち時間(`timeoutMS`・`timeoutFactor`)は `stryker.config.mjs` に書いておらず、Stryker の既定のまま

2026-10-18、利用者が「直して、これからも防ぐ」と決めた。理由は次の2つ。

- 時間切れは「テストが止まった」ことしか言わず、変異を見抜いた証拠として弱い
- 時間切れの変異体は、1体ごとに待ち時間を使い切るまで待つ

## Decision

1. **時間切れを落ちと数える。** `scripts/run-mutation.mjs` が、Stryker が走り終えた後にその回の結果を調べ、時間切れが1体でもあれば、
   ファイル・行・列・変異の種類・置き換えた後の文字列を出して終了コード1で終わる。時間切れが無ければ何もせず、Stryker の終了コードのまま終わる
   - その回の結果は、Stryker の `runMutationTest()` の返り値で取る。その回に走らせた変異体と結果ファイルから引き継いだ変異体を合わせた全部で、Stryker が点数を出して結果ファイルへ書くのと同じもの。
     取り方を選んだ理由と、Stryker の版が変わって取れなくなったときに落とす手当ては `scripts/run-mutation.mjs` の注釈
2. **時間切れを前回の結果から引き継がない。** 走らせる前に結果ファイルから取り除き、その回に必ず測り直させる(生き残り・どのテストも通らない変異体と同じ扱い)。
   引き継ぐと、コードを直しても前回の時間切れを使い回して落ち続けうる
3. **待ち時間(`timeoutMS`・`timeoutFactor`)は変えない。** 遅いだけで時間切れになった変異体も落ちと数える。直すのはコードかテストの方
4. 割り込まれたときに途中の結果を残す Stryker の処理と、その終了コード(128 + シグナルの番号)は変えない

## Consequences

- **ループ・再帰は、変異しても終わる形で書く必要がある。** `for (let i = 0; i < n; i++)` は `i++` を `i--` にした変異で止まらなくなり、時間切れで落ちる。
  上の実測のモジュールは、回数を配列の長さで決める形(`Array.from({ length: n }, …)` と `reduce`)に直すと、5体すべてを落として終了コード0で通った。
  書き方の決まりは [../quality/test-strategy.md](../quality/test-strategy.md) の「ミューテーションテスト」
- **失うもの: 時間切れで「落とした」と数えていた変異体が、落ちに変わる。** 無限ループを起こす変異は振る舞いを壊しているので、今までは時間切れで見抜いたと数えていたが、
  これからはテストが値で見抜ける形へコードを直すまで通らない。素直に書ける数え上げのループも、そのままでは置けなくなる
- **遅さや負荷で時間切れになった変異体も落ちる。** 待ち時間を延ばさないので、ふだんは落とせる変異体が、遅い機器・混んだ CI で時間切れになると、その回の `npm run test:mutation` が落ちる。
  そのときはテストを速くするかコードを直す。時間切れは引き継がないので、次の回には測り直される
- 入れた時点で時間切れが残っていると、push の CI の変異テストが落ちる。既存の時間切れ(0014 の時点で23体)をコードの形を直して落としてから入れる
- その23体は、数え上げを `src/utils/range.ts` の `range` の上を回す形にし、BFS の3か所(経路の `findPath`・`nearestReachable` と村ワールドの検査の開始セルからの歩数)を
  `src/lib/village/reach-cells.ts` に集約して直した。その後の全体の実行(2026-10-18、`--force`)は、4070体すべてが Killed で時間切れ0、6分3秒だった
- `npx stryker run` を直接叩くと、この判定を通らない(`scripts/run-mutation.mjs` の外)。時間切れがあっても通り、時間切れを引き継ぐ
- 時間切れの数は、今まではしきい値に影響しなかったので画面の表(`# timeout` の列)でしか見えなかった。これからは落ちたときの行に、どのファイルの何行目かが出る

## Alternatives Considered

- **時間切れを今までどおり落とした数に入れる**(Stryker の既定) — 利用者が退けた
- **待ち時間を延ばし、遅いだけの時間切れを減らす** — 採らない(Decision の3)。延ばすと、止まらなくなる変異体1体ごとの待ちも延びる
- その回の結果の取り方として、走り終えた後に結果ファイルを読み直す形と、リポーターを足す形を比べた。理由は `scripts/run-mutation.mjs` の注釈
- ほかに比べた案の記録は無い
