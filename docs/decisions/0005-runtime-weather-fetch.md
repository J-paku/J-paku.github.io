# 0005. 村の天気だけ実行時に外部 API を呼ぶ

## Status

Accepted(2026-09-20、`5fcd9a1` 「村に昼夜と天気を追加し描画と転送量を最適化」。実装は `src/lib/weather.ts`)

## Context

このサイトは静的エクスポートで自己完結しており、実行時に外へ出る通信を持たなかった。
村の空に実際の大阪の天気を反映したかったが、ビルド時に取り込むと**配信した瞬間に古くなる**。

## Decision

**この1件だけを例外**として、村の表示後にクライアントから Open-Meteo(API キー不要)を呼ぶ。

- 送るのは固定の緯度経度だけ。訪問者の位置情報は扱わず、応答も保存しない
- タイムアウトは5秒。**失敗・タイムアウト・応答形の不一致・オフラインはすべて `'none'` に丸める**
- 雨が降らないのはバグではなくフォールバック、という前提でテストも書く

## Consequences

- 村の空が実際の天気に追随する
- 外部サービスの停止がサイトの動作に波及しない(降らなくなるだけ)
- 例外が1つできたため、**次に外部通信を足したくなったときの判断基準**が要る → [../quality/security.md](../quality/security.md) の3条件
- E2E は応答を差し替えて雨あり・なしの両方を確かめる必要がある(`tests/day-night.spec.ts`)

## Alternatives Considered

- **ビルド時に取得して埋め込む** — 配信時点の天気で固定され、意味が無い
- **天気を諦めて時間帯だけにする** — 実際に採れた案だが、実物の街を写すという趣旨が弱くなる
- **API キーを要するサービス** — 静的エクスポートではキーが公開されるため採らない
