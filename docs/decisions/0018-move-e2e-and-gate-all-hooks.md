## Context

## Decision

### 移す E2E と消す手順

- 0016 の表の「統合へ移す」11ファイル(layout・day-night・night-transition・clock・dialog-focus・fishing・idle-loop・flight・umbrella・story・scene-refetch)を、この作業で統合テストへ移す。
  移す先は、その振る舞いを描くコンテナの隣の `container.browser.test.tsx`(0017 の D5)。同じフォルダで使い回す手順(歩く・押す・時間を進める・マスを読むなど)は、同じフォルダの `*.test-helper.ts` に置いてよい
- 0016 の「E2E を消す条件」を、E2E のテスト1件ずつに当てはめる。
  1. E2E のテスト1件ごとに、同じ利用者に見える振る舞いを断定する統合テストを書く
  2. その E2E が落とす欠陥を1つ以上選び、欠陥を入れると統合テストが落ちることを確かめる
  3. ビルドした配信物で、同じ欠陥で E2E も落ちることを確かめてから、その E2E を消す
  4. どの欠陥を入れて、どの統合テストとどの E2E が落ちたかは、消すコミットの本文に書く
- 同じ欠陥を統合テストが落とせない E2E のテストは消さず、E2E に残る(0016 の条件のまま)
- モックはネットワークと時間だけ(0017 の D6)。ビューポートの大きさや `prefers-reduced-motion` など、ブラウザの環境の設定はモックに数えない
- 「E2E に残す」5ファイルは、この作業では変えない。journey のうち 0016 が行き先を決めていないテストも、ここでは決めない

### フックのファイル別100%

- **対象は `src/**/hooks/**` の全部**(`src/hooks/` を含む)。一覧を手で並べず、新しいフックは置いた時点で対象になる。0016 のフォルダの一覧と、それを減らせないようにする検査は作らない
- 測るのは統合テストのカバレッジ(`vitest.integration.config.ts` の `coverage`。CI が走らせる `npm run test:integration -- --coverage`)。文・分岐・関数・行のそれぞれで100%にし、1つでも測られない所があれば落ちる
- 単体のカバレッジ(`vitest.config.ts`)は今までどおりフックを測らない。変異テストの対象にもフックは入れない(0016)
- コンポーネント(`.tsx`)のファイル別100%は、このADRでは決めない

### カバレッジから行を外してよいのは、E2E が見ている行だけ

- **統合テストで構造上届かない行**(`IntersectionObserver` の無い環境のように、E2E だけが作れる場合の分岐)は、その行の前に次の注釈を書いてカバレッジから外す。
  注釈は、その行を見ている E2E の spec のファイルとテストの名前を名指しする

  `/* v8 ignore next -- e2e: tests/<file>.spec.ts > <E2E のテスト名> */`

- 注釈が指す spec のファイルとテストの名前が実在するかを、機械で検査する。理由(e2e の参照)の無い v8・istanbul・c8 の除外の注釈は、この検査が落とす。
  検査の名前と置き場は、門を入れる段階で決める(決めた結果は `scripts/check-coverage-ignores.mjs` で、`npm run test:boundary` が走らせる)
- **注釈の直後に置けるのは、1行に収まる文(`if (…) return` など)だけ。** `v8 ignore next` は注釈の直後から始まる構文をまるごと外すので、
  複数行の文(`useEffect(…)` の呼び出し・ブロックを持つ `if` など)の前に置くと、その全体がカバレッジから消える。
  直後に構文の無い注釈(閉じ括弧・別の注釈の前・ファイルの終わり)は何も外さない。どちらも上の検査が落とす。外したい所は、注釈のすぐ下の1行の文に切り出す
- **どの層のテストも通れない防御の分岐は、注釈で外さない。** 振る舞いを変えずに、分岐の生まれない形へ書き換える(ref のコールバックで要素を受け取る・純粋関数へ切り出して単体で測る、など)。
  書き換えられないものだけ、別に利用者が判断する
- よって、カバレッジから外す注釈は `v8 ignore next -- e2e:` の1種だけになる
- [0011](0011-extreme-constraints.md)は、下限を下げることと門の対象から外すことに新しいADRを求める。注釈で行を外すことはそれに当たるので、このADRが決めたこととし、外してよい行を上の条件に限る

### 1つの PR で入れる

ブランチ test/e2e-to-integration の1つの PR で、11本を移すことと、フックの門(注釈とその検査を含む)を入れる。
0016 の「フォルダごとに複数のセッションに分けうる」に対する利用者の決定で、不変ルール6「1段階 = 1セッション」([../../AGENTS.md](../../AGENTS.md))そのものは変えない

## Consequences

- **フックは、それを使うコンテナの統合テストで全部の行を通すことが門になる。** 新しいフックは置いた時点で100%の対象になる。統合テストで通らない分岐をフックに残すと落ちるので、
  ロジックは純粋関数へ、起きない場合の防御は分岐の生まれない形へ移す
- **E2E を名指しする注釈は、その E2E を残す理由にもなる。** 注釈が指す E2E を消したり名前を変えたりすると検査が落ちるので、行を外す根拠が消えたまま残らない
- **注釈が実際に効くかは、門を入れるときに確かめる。** Vitest の v8 のカバレッジが、ソースの変換を経た後もこの形の注釈を読むかは、決めた時点では測っていなかった。
  門を入れるときに、注釈を外すと落ち、付けると通るのを一度見てから採る([../quality/test-strategy.md](../quality/test-strategy.md) の「新しい検査は必ず一度落とす」)。
  2026-10-15 に、注釈を外すとフックのファイル別100%が落ち、付けると通るのを見て確かめた(Vite の変換を経ても注釈が効き、`@preserve` などの印は要らなかった。`scripts/check-coverage-ignores.mjs` の冒頭の注釈)
- **E2E を消すコミットでは、その spec を名指ししている文書も直す。** `npm run docs:check` が、[../quality/test-strategy.md](../quality/test-strategy.md) の E2E の一覧と見出しの本数と、文書に書いた `tests/` のパスの実在を突き合わせる
- **偽の時計に当たりうる。** 時計・昼夜・夜への移り変わり・作品ストーリーの自動送りは時間を差し替えるので、locator の操作が時計を進めない([vitest-dev/vitest#10058](https://github.com/vitest-dev/vitest/issues/10058)。0016 の Consequences)ことに当たりうる
- 統合テストの全体の床(実測から2pt引いた値)は、移した後の実測で上げてよい(上げる方向は ADR が要らない。0011)
- CI の時間は、E2E が減り、統合テストが増える。どちらも測っていない

### 実施の結果

2026-10-15 に行った。

- **移した E2E。** 「統合へ移す」11ファイルの70件のうち、62件を統合テストへ移して消した。件数は `npx playwright test --list` で数えた
  (ja/ko のループは言語ごとに1件と数えるので、Context の63件(spec の中の test() の数)とは数え方が違う)。
  spec ごとの消した件数/元の件数は、layout 6/7・day-night 6/8・night-transition 0/3・clock 9/10・dialog-focus 5/5・fishing 9/10・idle-loop 4/4・flight 12/12・umbrella 5/5・story 5/5・scene-refetch 1/1。
  dialog-focus・idle-loop・flight・umbrella・story・scene-refetch の6ファイルは spec ごと消した。
  移した先は、村は `src/components/VillagePage/` の、作品ストーリーは `src/components/Story/` の `container.browser.test.tsx`(どちらも当時の置き場。[0019](0019-hooks-make-containers.md) で `__tests__` の下へ移した)
- **欠陥の入れ方。** 消した E2E のテストの1件ごとに、製品のコードへ欠陥を入れ、ビルドした配信物でその E2E が落ち、対応する統合テストも落ちるのを確かめてから消した。
  欠陥を入れたパッチはコミットしていない
- **E2E に残したテスト(8件)と理由。**
  - `tests/fishing.spec.ts` の「投げる・かかる・釣り上げるの各コマは足元と立ち位置を残して体だけが動き、動き終えれば歩行ループが眠る」:
    体の画素を構えのコマと比べるには、ビルドが焼くシートとローダーのスプライトの背景が要り、統合テストでは描かれない。
    右向きの張るコマに構えの絵を当てる欠陥は、コマの名前は替わるので統合テストでは落ちず、この E2E だけが落とした。コマの時間割・左右反転・立ち位置・歩行ループの眠りは統合テストへ移した
  - `tests/layout.spec.ts` の「PC: 一覧への出口は右下に固定される (/ko/)」: 統合のフィクスチャは ja の props だけを渡す。ja の側は統合テストへ移した
  - `tests/day-night.spec.ts` の「4段階のどれも属性だけでなく焼いたシートそのものが入れ替わる (/)」: 段階ごとのシートが別物で読めるかは、ビルドが焼く `/sprites/` の PNG とローダーの `<style>` が要る。
    段階の属性(`data-phase`)の部分は統合テストにも足した
  - `tests/day-night.spec.ts` の「夜で雨でも8か所のコースは最後まで通る (/ko)」: ko の全部の地点の文言で次へを連ねる完走([0015](0015-trim-e2e-overlap-and-ko.md))。
    統合のフィクスチャは ja の props だけを渡す。ja の完走は統合テストへ移した
  - `tests/night-transition.spec.ts` の3件: 描いた背景がその段階の焼いたシートを指し、画像として読めるかは、焼いたシートとローダーの `<style>` が要る。
    段階の切り替えとシート2枚の取得・decode 待ちは統合テストにも足した
  - `tests/clock.spec.ts` の「卓上時計で 20:00 を決めると夜になり、町へ出ても続き、再読み込みで実時刻へ戻る (/)」: 再読み込みは統合テストの中では作れない
    (読み込み直すとテストごと消え、ストアを手で戻しても再読み込みの代わりにならない)。再読み込みの前までは統合テストにも足した
- **実施後の E2E** は10ファイル・71件(2026-10-15 の `npx playwright test --list`)。統合テストはコンテナごとに1本の6ファイルのまま
- **`v8 ignore next -- e2e:` の注釈**は2つで、どちらも `tests/observer-missing.spec.ts` を指す(一覧の作品カードの use-fully-visible と、作品ストーリーの use-active-scene)
- **フックは全部(`src/**/hooks/**`)がファイル別100%** になり、統合テストのカバレッジの門(`vitest.integration.config.ts`)を通る
- **書き換えた防御の分岐。** 起きない場合を注釈で外さず、その場合のコードが無い形へ書き換えた。
  - use-joystick-drag: ref の null の検査(土台とつまみを常に描く)
  - use-scroll-thumb
  - use-badge-layout: 間引き(throttle)をやめ、前の予約を取り消してから次のフレームを頼む形にした
  - use-map-focus: `?? null` で受ける形にした
  - use-dialog-focus: `open: true` を値として書く形にした
  - use-stage-scale: `exit` を必須にし、舞台・操作帯・出口を常に描く
  - use-clock-modal: 1段目のボタンは常に押せる
  - use-village-arrive: 着いたマスには必ず地点がある
  - use-village-umbrella: 印は常に開く側
  - use-fishing-pose
  - use-village-fishing: 始める時の検査。pickCatch は、openTalk が先に釣れる物の有無を見るので null にならない
  - use-village-overlay: openTalk の錠の検査(`if (runtime.locked.current) return`)を外した。錠の間に呼ばれるのは autoTalk の地点に着いてから描き直すまでに Z を押した時だけで、
    会話・時計の窓を開き直しても窓は1つのまま(訪問済みは数えない)。釣りは押した入力からしか始まらず、同期で描き直すので2度は始まらない
  - use-village-runtime: 何もしない既定の関数をやめ、null と `?.` で呼ぶ形にした
  - use-walk-loop: 止めたループの wake を何もしない手へ差し替えるのをやめた(止めたループは wake されても回らない)。枠の幅を覚える effect は枠の null を検査しない(ref は effect より先に付く)。
    フレームの中の枠の null の検査は残した。最初の ResizeObserver の知らせより前、フレームを待っている間に村を外すと本当に通る道で、
    統合テストの「描いた直後、枠の幅の最初の知らせが届く前に村を離れ、後片付けより先に最初のフレームが来ても、歩行ループは外れた枠を読まない」が通す
- CI の時間(E2E と統合テスト): まだ測っていない

## Alternatives Considered

- **0016 のとおり、フォルダの一覧を段階で広げる** — 利用者が退けた。利用者が述べた理由は、0016 の終わりの形(一覧を消して全フックを対象にする規則)へ直接行くこと。
  補足すると、この作業で「統合へ移す」の11本を全部移すので、一覧と、一覧を減らせないようにする検査は、同じ PR の中で作って消すことになる
- **統合テストで届かない行を持つファイルを一覧にして、ファイル別100%から外す** — 利用者が採らなかった。退けた理由は記録が無い。
  補足すると、ファイルごと外すと、同じファイルの中で統合テストが通る行(`IntersectionObserver` がある時の道など)も門から外れ、一覧は外す理由もその行を見ている E2E も名指ししない
- **理由を書いた別の注釈(`unreachable:` など)を許し、どの層も通れない防御の分岐を外す** — 利用者が採らなかった。分岐の生まれない形へ書き換えることを選んだ(Decision)。退けた理由は記録が無い。
  補足すると、e2e の注釈は指す先の実在を機械で突き合わせられるが、「起きない」という理由には突き合わせる相手が無い
- **例外なく100%にする(注釈も一覧も持たない)** — 利用者は E2E を名指しする注釈を選んだ。
  補足すると、統合テストで作れない場合(`IntersectionObserver` の無い環境。Context)があるので、例外なしで門を通すにはモジュールをモックすることになり、0017 の D6(モックはネットワークと時間だけ)に反する
